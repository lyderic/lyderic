Wireguard hub-and-spoke on Incus/OpenWRT

18 juillet 2026

OpenWRT is not only for cheap Wifi routers. It can be used wherever one needs a solid network stack based on Linux. All the Linux network commands can be used (ip, nft, brctl, dnsmasq…), but also, a very nice cli configuration tool (uci) is provided as well as an advanced GUI (LuCI).

When you rent a VPS and want cleanly separated containers, nothing beats incus. If you use this VPS as your Wireguard hub in an hub-and-spoke topology, is it possible to use Wireguard in incus? Turns out it is. This post explains what needs to be done to make it happen.

Prerequisites

Don’t try this if you’re not very familiar with incus and OpenWRT. You also have to be very comfortable in Linux system administration and networking.

Any VPS where incus can run (I have a cheapo with only 2 cores and 2GB of RAM) will do. OpenWRT is incredibly lean.

My setup is (most recent versions as at the time of this writing):

  • Arch Linux

  • Current incus (not LTS): version 7.2

  • OpenWRT, incus image: 25.12 (images:openwrt/25.12)

Container

Launch an OpenWRT incus container. I call it ‘bob’. ‘bob’ will also be the name of the domain. Simples.

$ incus launch images:openwrt/25.12 bob

Find out your incusbr0 network:

$ incus network list incusbr0 -c4 -fcsv
10.42.20.0/24

For the container to eb accesible on TCP/80, TCP/443 and UDP/50819 (arbitrary Wireguard port): assign a fixed IP to the OpenWRT container and setup NAT’ed proxy devices (1.2.3.4 is the VPS’s public IP):

$ incus config device override maple eth0 ipv4.address=10.42.20.4
$ incus config device add bob luci80 proxy listen=tcp:1.2.3.4:7780 \
connect=tcp:10.42.20.4:80 nat=true
$ incus config device add bob luci proxy listen=tcp:1.2.3.4:77443 \
connect=tcp:10.42.20.4:443 nat=true
$ incus config device add bob wg proxy listen=udp:1.2.3.4:50819 \
connect=udp:10.42.20.4:50819 nat=true

Enter the container, check the ip address and drop the firewall to be able to connect to the GUI (by default, there is only a WAN interface, that blocks GUI access):

$ incus exec bob sh
# ip a
# service firewall stop
# service firewall disable
# exit

Now you should have GUI access to your Wireguard container. In a browser enter:

http://1.2.3.4:7780

This is super insecure at this stage: immediately set up a strong root password and enforce HTTPS:

System > Administration > HTTP(S) Access
⇶ Redirect to HTTPS (checked ✓)

Best is you have TLS certificate and key: you can deploy them into resp. /etc/uhttpd.cert and /etc/uhttpd.key. TLS creation is outside of the scope of this post. You can also run a reverse HTTPS to HTTP proxy (Caddy, nginx, traefic…), a Cloudflare tunnel or anything, but please don’t keep HTTP:

$ incus config device remove bob luci80

Install Wireguard

This is easier done on the cli:

# apk update
# apk upgrade
# apk add luci-proto-wireguard
# reboot

Configure Wireguard hub interface

We decide that the Wireguard network will be 10.0.12.0/24 (this is completely arbitrary). The OpenWRT container will be 10.0.12.1 and will also be the DNS server.

Create a new interface:

  • Network > Interfaces > Add new interface…

  • Name = wg0, Protocol = Wireguard

Tab: General Settings

  • Generate a new key pair

  • Listen Port = 50819

  • IP Addresses = 10.0.12.1/32

  • Leave No Host Routes unchecked

Tab: Advanced Settings

  • Make sure that Use default gateway is unchecked

Tab: Firewall Settings

No really relevant, as we dropped the firewall, but check that the interface is in the WAN zone.

Tab: DHCP Server

No DHCP server for this interface. We’re doing 100% static ip.

Tab: Peers

See below

Add a peer

Now that we have a hub, we can add a new peer to it. To test the thing, let’s have a phone connect to the hub. On the phone (called ‘sams’), we install the Wireguard app. And on the Peers tab, we click on Add peer.

  • Description = sams

  • Generate new key pair

  • Allowed IPs = 10.0.12.5/32 (pick any free IP)

  • Persistent Keep Alive = 25

Then click at the bottom on ‘Configuration Export’ > ‘Generate Configuration’:

  • Connection endpoint = IP or FQDN of the VPS

  • Allowed IPs = 10.0.12.0/24 (remove 0.0.0.0/0 and ::/0)

  • DNS Servers = 10.0.12.1

  • Addresses = 10.0.12.5/32

At this point, you can either download a conf file (for your PC) or scan the QR code (for your phone). Deploying a Wireguard client configuration on a phone or a PC is outside of the scope of this post.

Then Save, Save, Save and apply. Restart network (System > Startup).

Routing

Now that the peers can see each other, we have to set up the routing:

In Network > Routing add a static IPv4 route as follows:

  • Interface = wg0

  • Route type = unicast

  • Target = 10.0.12.0/24

  • Gateway = 10.0.12.1

DNS

Finally, we have to make the DNS server active on the wg0 interface:

In Network > DNS:

Tab: Devices and Ports

  • Listen interfaces = wg0

  • Listen addresses = 10.0.32.1[wg0]

Tab: DNS Records

  • Add the static IPs of all the peers you create

  • Restart network and dnsmasq

If all works well, you should be able to ping any peer from any peer by names such as foo.bob.
